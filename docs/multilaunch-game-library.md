# Account batch launch and game library

The local implementation separates singleton readiness from account/game verification. Player starts remain serialized; a confirmed worker `OK` releases the next start while prior joins are observed in the background. This uses the existing worker wire protocol and does not require a new scheduled worker or automatic installation.

The account provider prepares at most one upcoming browser session, issues tickets immediately before startup, reuses the launch service baseline, and shares a serialized 750 ms discovery cache. Each join has a 60-second budget measured from player handoff. Native diagnostics record stage names and elapsed milliseconds, without account IDs, cookies, tickets, game IDs, server IDs or log contents. Failure to confirm helper readiness stops pending starts. Cancellation never retries a handoff or closes running players.

Checked targets resolve public experience metadata and square game icons, with landscape/placeholder fallback. Image MIME types are normalized, including Roblox's `image/Png` responses. Artwork is bounded and fetched natively, never with account cookies. Recent games retain 20 distinct requested places in local storage after player handoff, with game metadata/art, ordered local account IDs, and the selected layout preset. History is atomic, private to the Windows account, and serialized across processes. Recent Play again repeats the saved account order and layout, independently of the current selection, and clears an explicit server override. Change accounts loads the saved batch into the launch form with an account picker; the next player handoff replaces the saved batch for that place. Missing accounts or an unavailable/incompatible preset require reviewing the batch first. Older entries without account IDs remain visible and require choosing accounts before replay. A partial or canceled batch with at least one player handoff retains the full requested batch; it is not a record of confirmed joins. Older cards with missing or non-icon artwork refresh in the background.

Account sign-in checks automatically for a secure Roblox session, validates identity through Roblox, and closes only after successful confirmation. Checks do not overlap; absent sessions are checked every two seconds, failed checks back off ten seconds, and rate limits back off one minute. Wrong identities, duplicate saved accounts and challenges keep the window open. Cancellation stops checks before browser cleanup. A final cookie read prevents accepting an identity from a session switched during validation. No Verify button is required.

Automatic public-server discovery reads at most three 100-entry pages in five seconds. Allocation sorts by free capacity, then ping, then ID. Unavailable capacity falls back to normal matchmaking. Later groups refresh capacity and conservatively reserve earlier batch assignments. Explicit Job IDs override planning. Planned and observed servers are separate; observing a server in a player log does not guarantee that later teleports keep accounts together. Friendship creation and guarantees of game-specific boosts are outside this implementation.

Latest refinement deliverable: `.build/desktop-account-refinements/RobloxMultiInstance.exe`. Close older desktop app windows before opening it, because the desktop's single-instance guard may otherwise activate an old process. The opt-in account fixture `--public-artwork PlaceId` checks the actual native public artwork downloader without reading account sessions or starting Roblox; Tap Simulator REBORN returned a ready square icon in this check.

Live acceptance remains pending: launch two selected accounts, check both account identities in-game, compare the planned server with actual server membership, then repeat for a batch exceeding a server's capacity. Measure authorization, singleton readiness, inter-player handoff, and join times from diagnostics. Verify slow/failed joins do not delay starts after readiness, cancellation leaves existing games open, and changed occupancy produces an explicit fallback. Do not infer live reliability or a fixed launch-time guarantee from fixtures.
