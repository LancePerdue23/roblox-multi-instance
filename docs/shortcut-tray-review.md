# Shortcut and tray review — November 9, 2026

Live Windows probes reproduced ERROR_HOTKEY_ALREADY_REGISTERED (1409) for Manager (Ctrl+Alt+M) and Saved (Ctrl+Alt+R). Both still failed after closing the development executable. Ctrl+Alt+S registered successfully. Windows does not report the owning process through RegisterHotKey. The sandbox instead returned ERROR_ACCESS_DENIED (5), demonstrating why the real error must be captured immediately.

Keyboard capture and display use the existing persisted WinForms-compatible encoding: Shift=0x10000, Ctrl=0x20000, Alt=0x40000, plus the virtual key. Manager is 393293 and Saved is 393298. Registration translates those flags to MOD_SHIFT=4, MOD_CONTROL=2, MOD_ALT=1 and MOD_NOREPEAT=0x4000. Capture now accepts the same letter/digit/F1–F11 combinations as validation, rejects unsupported Windows-key combinations, preserves Tab navigation, and handles shifted digit keys. Own hotkeys are suspended while a binding field has focus so they do not consume the capture keystroke; another application's registration can still consume it.

Saving validates the complete schema, names commands with invalid/duplicate bindings, and preserves existing settings on rejection. Fresh-backend reload tests cover Ctrl+Alt+M and Saved. Active/requested registrations are retried after save, reset and import. Native results publish successful counts and enabled/partial/failed/disabled/capturing states. A failed-all attempt releases ownership; a partial attempt retains its successful registrations. Capture retains the ownership lock while temporarily releasing registrations. Disabling is idempotent.

Tray lifetime code review: enabling tray alone does not enable shortcuts; successful shortcut registration ensures a tray icon exists. Close hides the window while tray mode is active; Reopen restores the existing window. Disabling tray releases shortcuts, reopens a hidden window, and disposes both icon and context menu. Disabling shortcuts leaves tray mode intact. Explicit Exit bypasses close-to-tray and releases shortcuts before waiting for background shutdown. Final disposal releases the owner and native message hook. Existing layout-operation close blocking remains in effect. Tray mode and shortcut activation remain session-only; saved bindings persist.
