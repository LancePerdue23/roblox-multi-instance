# Supporter preview isolation

Normal frontend builds exclude the unrestricted supporter-preview shell and its URL route. Badge previews remain public on the Support page. Unlock replay is enabled only at or below the verified tier (the higher verified cumulative USD or Robux tier, with legacy receipts retaining base Supporter). The Vite compile-time flag defaults false; only `npm run build -- --mode local-supporters` includes the unrestricted shell. Normal verified supporters use Ember, Orbit and Radiant artwork with a persistent animation preference. Saved Classic selections move to the new artwork without changing entitlement. Classic code and styles are archived outside the frontend and excluded from release bundles. Previewing a higher tier does not change actual displayed entitlement.

Local preview output carries `local-supporter-preview.json`. Package.ps1 refuses that marker or a local-role-switcher.js payload, including when -SkipFrontend reuses assets. Normal desktop builds remove stale local marker/switcher files before copying normal assets. The ignored local launcher rebuilds preview mode and injects the ignored cosmetic role override into the development output only. Do not distribute the development output as a release; use Package.ps1.

The local override never writes backend receipts, pass ownership, or account state. No username-based or query-string role grant exists. The backend rejects support.setRole. Stripe receipt imports require a trusted signing key and valid signature; Roblox recognition requires a positive configured-pass ownership check.

Security boundary: the existing Roblox offline cache is protected with Windows CurrentUser DPAPI, not signed by a server. A user controlling their Windows account can construct DPAPI-protected data, and a modified client can draw any cosmetic badge. This design prevents accidental preview exposure and ordinary UI/bridge role changes; it does not provide tamper-proof offline entitlement. Strong Roblox entitlement proof would require a server-verified, signed receipt bound to authenticated account identity. The approved Robux catalog and cumulative tiers are bundled; Stripe remains disabled in the default configuration.

The ignored owner dropdown dispatches preview events to the React renderer for supporter roles, so owner previews use the same Ember, Orbit and Radiant art and unlock code as the Support page. These listeners/components are guarded by the owner-only build flag. The scripted Default option remains a navigation shortcut; it does not grant support.

The owner panel includes Add recognition badges checkboxes. These add any subset of the four recognition kinds alongside the existing selected role (including a supporter tier), and persist independently under a local preview key. Duplicate kinds are collapsed. Toggling extra badges is quiet and grants no receipts or account recognition. Existing visibility preferences still apply. Actual production supporter status and signed account recognition are independent and can coexist; the earlier mutually exclusive dropdown was only a preview limitation.

## Development credit simulation

The local-supporters build adds Dev credit controls to the Robux section: Simulated Robux credit, Apply, Add selected pass, and Use real credit. Values are nonnegative safe whole numbers and persist only under rmi.local-support-credit. Active simulation is visibly labeled and overrides manual supporter-role preview for the slider, shifted milestones, tier cards, sidebar, cosmetics and upgrade animations. Same-tier edits and reopening stay quiet. Reset removes the simulation preference and restores actual credit and existing role preview.

Simulation never calls a credit-changing native command or writes a purchase ledger, receipt or account record. Normal builds exclude controls and the preference key, ignore injected preview preferences, and retain packaging exclusion of preview artifacts. Native ownership fixtures independently exercise real cumulative aggregation, cancellation and offline persistence.

### Cold verification reset

Dev credit controls → Reset credit checks clears the protected Robux purchase ledger, the legacy Robux recognition marker, and in-memory check/cooldown state. It returns simulated credit and the local role selector to actual status. Previously verified account/pass pairs are checked against Roblox again on the next verification. USD receipts, wallet recovery, account sessions and badge preferences are retained. The reset button performs this explicit local reset when pressed; creating or rebuilding the button does not clear existing credit.

The native support.devResetRoblox command requires confirmed: true and the LOCAL_SUPPORTER_TOOLS compile flag. The default development build sets LocalSupporterTools only when its local preview marker is present. Explicit output/package builds disable that native capability, and normal frontend bundles exclude the reset UI and command. Reset waits for any active verification to finish so late responses cannot restore cleared credit.
